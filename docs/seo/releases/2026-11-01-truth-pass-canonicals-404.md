## The four corrections, and what each produced

### 1. "Your canonicals are not self-referential" — accepted

Measured live 2026-11-01 14:55 (+08): `https://homemassageubud.com/` → `307` → `https://www.homemassageubud.com/` → `200`.
The 157 canonicals and 154 sitemap locs are on the apex. So each one names a URL that redirects.

Two options were offered: point everything at the served host, or record the defect. **Decision: record
it, do not move the host.** Reasons: (a) the apex is the recorded target, and Google's canonical
resolution follows the 307 to www anyway, so today's consolidation lands on the same URL either way;
(b) moving 157 canonicals to www now means moving them back when the primary domain is flipped, two
URL migrations for one outcome; (c) when the flip happens the apex becomes the 200 host and every
canonical and sitemap loc is already correct with no code change.

What did change, so this cannot be reported green again:
- `scripts/prerender.mjs` no longer hardcodes the origin in two places. `SITE_ORIGIN` (default
  `https://homemassageubud.com`) feeds canonicals, `og:url` and the generated sitemap. Host flip = one value.
- The build now prints the canonical host on every build and warns (`DEFECT-D-1`) when
  `SERVED_HOST` is set and does not match.
- `docs/seo/KNOWN-DEFECTS.md` — new file, DEFECT-D-1 with the live measurement, the both-hosts
  Search Console evidence and the single action that closes it.
- Correction appended to the 2026-11-01 release record (below).

Search Console evidence that the split is real, not theoretical (2026-08-03..2026-11-01, by page):
`/amed` apex 10 clicks/192 impressions **and** www 2 clicks/64; `/legian` apex 4/54 **and** www 4/54;
`/uluwatu` www only 11/419; `/nail-care` www only 14/445; plus an `http://homemassageubud.com/` row.
Google is holding both hosts because the redirect is 307 (temporary).

### 2. "`/bali` is not one path" — accepted and fixed at the cause

Measured before: `/nonexistent-xyz-123` → `200`, 13,669 B; `/sitemap-foobar.xml` → `200`, 13,669 B.
Cause: `vercel.json` rewrote `/(.*)` to `/`, so the catch-all was every unknown path including unknown
`.xml`, each answering with the homepage under a 200 status.

Fix: the catch-all rewrite is gone. `dist/404.html` is generated by the prerender step — title
`Page not found | Home Massage Ubud`, `robots: noindex, follow`, **no canonical**, static `<h1>Page not
found</h1>`. Vercel serves it with a real `404` status for anything not prerendered. The old
`client/public/404.html` was a GitHub-Pages "Redirecting…" stub with a `meta refresh`; it is deleted, and
the build fails if that pattern reappears.

### 4. "sitemap.xml still lists three Kuta URLs" — accepted, unlisted

sitemap.xml carried `/kuta`, `/villa-massage/cities/kuta`, `/blog/premium-home-massage-kuta`.
Search Console by page, 2026-08-03..2026-11-01: **all three have 0 clicks and 0 impressions** — they do
not appear in the page report at all. So there is no traffic to protect and nothing to weigh against.

Decision: **unlisted, not redirected and not deleted.** They stay served and indexable (`200`, own title,
own canonical) because deleting a URL on the Ubud host that sells a Kuta service is David's
cross-domain call, and because the standing rule from 2026-11-01 forbids removing a URL without an
indexed replacement. They are simply no longer advertised: `route-meta.json` gains
`"sitemap": false` plus a `reason` for each, and the build fails on an unlisted route without one.

sitemap.xml is now **generated from the manifest** (154 locs) instead of hand-maintained XML, so the
sitemap and the prerendered head cannot drift apart again.

Also removed while in there: `sitemap-index.xml` and the eight `sitemap-*.xml` family files, all
`lastmod 2026-01-20`, three of which still listed Kuta URLs. Search Console knows one sitemap only —
`sitemap.xml`, 157 submitted, 0 errors, last downloaded 06:44:57Z on 2026-11-01 — so nothing was
submitted there and nothing is lost.

## Gates (fail-closed, unchanged in spirit)

- every manifest route needs a title 50–60, a description 120–155, an `<h1>`.
- no duplicate titles.
- `sitemap: false` requires a `reason`.
- generated sitemap loc count must equal the listed count; an unlisted route in the sitemap fails the build.
- generated `404.html` must be `noindex`, must carry no canonical, and must not carry a `meta refresh`.
- spot-checked routes must exist with the exact expected canonical.
